The `dolphin` CLI talks to a running Dolphin runtime. Use it when a shell script or agent needs to inspect worktrees, launch terminals, open files, automate the built-in browser, or report progress back into Dolphin.

## Verify the runtime

Register the CLI under [Settings → General → Dolphin CLI](/docs/settings), then check that it can reach Dolphin.

The command is `dolphin` on macOS, Windows and Linux alike:

```bash
command -v dolphin
dolphin status --json
```

If Dolphin is not already running:

```bash
dolphin open --json
dolphin status --json
```

Use `--json` when another tool will parse the result. Human-readable output is for quick terminal checks.

## Selectors

Most commands accept selectors instead of requiring long IDs:

```bash
dolphin repo show --repo id:<repoId> --json
dolphin worktree show --worktree active --json
dolphin worktree show --worktree path:/abs/path/to/worktree --json
dolphin worktree show --worktree branch:feature-name --json
dolphin worktree show --worktree issue:123 --json
```

`active` and `current` resolve to the enclosing Dolphin-managed worktree from the shell's current directory or terminal context. Use explicit selectors in scripts that may run outside the target worktree. For remote runtimes, prefer full server-side selectors such as `id:<repoId>::<absolute-worktree-path>` or `path:<absolute-server-path>` because the local shell's current directory may not exist on the runtime host.

## Choose a host

List every machine the current Dolphin host can target and the selector for each one:

```bash
dolphin host list --json
```

The result includes this machine, its registered [SSH targets](/docs/ssh), and paired [Remote Dolphin Servers](/docs/remote-servers). Use `--host local` for this machine, `--host ssh:<target-id>` for an SSH target, and `--environment <server-name>` for a paired server. SSH rows include the detected remote platform (`linux`, `darwin`, or `win32`) after the target connects; older or disconnected targets report `platform unknown`. They also include `connected` and, when known, the SSH lifecycle `connectionStatus`. If you put a machine name on the wrong selector, Dolphin reports the matching machine and the flag to use instead of returning an empty result.

`--host` also takes the bare name shown in the `name` column, on either axis — `--host trader-local` reaches the same machine as `--host ssh:ssh-1783599077486-fyasux`. Names resolve only when they are unique: a name held by two SSH targets, by two paired servers, or by one of each is refused, and the error hands back the id form for each candidate — `--host ssh:<target-id>` for an SSH target and `--host runtime:<environment-id>` for a paired server. Use those to settle it, since `--environment <server-name>` cannot separate two servers sharing a name.

Remove a saved SSH target with the id `dolphin host list` prints:

```bash
dolphin host rm --host ssh:<target-id> --json
```

It removes the target the same way Settings does, so the passive `~/.ssh/config` import does not add the alias back on the next launch. It takes only the `ssh:<target-id>` form, not the bare name, because it deletes data. It refuses `--host local`, paired servers (use `dolphin environment rm`), and an id this Dolphin host does not have.

## Runtime commands

```bash
dolphin open --json
dolphin status --json
dolphin serve --port 6768 --bind 100.64.1.20 --pairing-address 100.64.1.20 --json
```

`dolphin serve` starts a runtime server in the foreground without opening the desktop window. Use it for [Remote Dolphin Servers](/docs/remote-servers) or headless environments, and stop it with `Ctrl-C`. It accepts clients from localhost, LAN and Tailscale addresses; add `--allow-public` to accept public internet addresses too.
Use `--bind <literal-ip>` to choose the listening interface; `--pairing-address` changes the address advertised to clients.

## Repos

```bash
dolphin repo list --json
dolphin repo add --path /abs/path/to/repo --json
dolphin repo add --path /abs/path/to/folder --kind folder --json
dolphin repo show --repo id:<repoId> --json
dolphin repo set-base-ref --repo id:<repoId> --ref origin/main --json
dolphin repo search-refs --repo id:<repoId> --query main --limit 10 --json
```

Set the repo base ref before creating lots of worktrees so new tasks branch from the right place by default.

`repo add` defaults to `--kind git`. Use `--kind folder` to open an ordinary directory, including a repo-tool root containing separate Git repositories, as a folder workspace without Git worktrees or source control. With `--environment`, use an absolute path on that Dolphin server.

## Worktrees

```bash
dolphin worktree list --repo id:<repoId> --json
dolphin worktree ps --json
dolphin worktree current --json
dolphin worktree show --worktree active --json
dolphin worktree create --repo id:<repoId> --name fix-login --json
dolphin worktree create --name child-task --agent codex --prompt "Investigate the flaky login test" --json
dolphin worktree set --worktree active --comment "reproduced failure; testing token refresh fix" --json
dolphin worktree set --worktree active --workspace-status in-review --unread --json
dolphin worktree rm --worktree id:<worktreeId> --force --json
```

When `worktree create` runs from inside a Dolphin-managed worktree, Dolphin records the new worktree as a child when it can infer the relationship. Pass `--parent-worktree active` to be explicit, or `--no-parent` when the new work is independent.

Pass `--branch DAT-111-fix-login` to name the Git branch yourself instead of applying the configured branch prefix. `--name` still sets the workspace name and `--base-branch` the starting ref. If that branch already exists and cannot be reused, or the workspace path is already taken, Dolphin appends a numeric suffix to both, as it does in the new-workspace composer, so `--name task --branch exact` can produce branch `exact-2` even when `exact` is free.

`worktree set --unread` puts the unread dot on the workspace in the sidebar, the same one Dolphin shows when an agent finishes; `--read` clears it.

Agent startup flags:

```bash
dolphin worktree create --name review-api --agent claude --setup run --json
dolphin worktree create --name quick-check --agent codex --prompt "Summarize the diff" --setup skip --json
dolphin worktree create --name hidden-setup --setup inherit --json
```

`--agent` launches the selected agent in the first terminal. `--prompt` sends initial work to that agent. `--setup run|skip|inherit` controls repo setup hooks; `inherit` follows the repo policy.

Link issues and reviews using the existing workspace metadata:

```bash
dolphin worktree create --repo id:<repoId> --name review-task --pr 123 --json
dolphin worktree create --repo id:<repoId> --name gitlab-task --gitlab-issue 42 --gitlab-mr 77 --json
dolphin worktree set --worktree active --gitlab-issue '#42' --gitlab-mr '!77' --json
dolphin worktree set --worktree active --gitlab-issue https://gitlab.example.com/group/project/-/work_items/42 --json
dolphin worktree set --worktree active --pr null --gitlab-mr null --json
```

`--pr` is a GitHub pull request number. `--gitlab-issue` accepts an issue number or `#42`; `--gitlab-mr` accepts a merge request number or `!77`. Numbers must be positive safe integers. The GitLab flags also accept HTTP(S) issue or merge request URLs, including self-hosted instances and nested groups. The URL's host and project must match the workspace's stored GitLab source context or the repository's stored remote. If that identity is missing or different, the command fails before updating metadata. A URL cannot choose another project, change the checkout, or fetch a review branch.

Omitting a flag leaves its link unchanged. On `set`, literal `null` clears only the named link; `create` refuses `null`. Each provider has separate fields, so setting a GitLab issue or merge request preserves GitHub and Linear links.

Folder-based repositories can store numeric links through these commands, but a number does not supply a provider host or project. Without existing source context or a stored remote, pasted GitLab URLs are refused and provider details or clickable links may be unavailable. These flags use fields already supported by the runtime; an older runtime that predates a field may ignore it, so check `worktree show --json` after writing to an older host.

## Ports

```bash
dolphin ports --json
dolphin ports --worktree branch:feature/login --json
dolphin ports --all
```

`ports` lists the listening ports Dolphin tied to a workspace, from the host the workspace runs on. It defaults to the workspace that contains the current directory. Each row has `port`, `pid`, `processName`, `connectHost`, `protocol`, how Dolphin matched it (`owner.confidence`: `cwd` or `command`), and `advertisedUrl` when the dev server printed one in a Dolphin terminal. `--all` lists every listener on that host. Native folder workspaces need `--all`, because Dolphin does not tie ports to them. If `unavailableReason` is set, the scan could not run on that host; SSH workspaces opened directly from the desktop report this for now, while a workspace on a managed Dolphin server is scanned on that server.

## References

A workspace can link multiple reviews and issues, including sources outside its repository.

```bash
dolphin reference list --worktree name:api --json
dolphin reference add https://github.com/acme/api/pull/5123 https://linear.app/acme/issue/STA-1234 --worktree name:api --json
dolphin reference remove https://github.com/acme/api/pull/5123 --worktree name:api --json
dolphin reference remove --key '<key-from-list>' --worktree name:api --json
dolphin worktree create --name fix --reference https://github.com/acme/api/pull/5123 --reference https://linear.app/acme/issue/STA-1234 --json
dolphin reference find STA-1234 --json
```

- **Writes:** full URLs only; no custom shorthand. `remove --key` supports older entries without URLs. Source-unknown legacy links cannot match an exact URL; native issue keys remain searchable when stored. Duplicate adds and absent removals are no-ops. Unrelated links and current selection are preserved. Older hosts without safe delta merging refuse writes.
- **Create:** repeat `--reference`; incompatible with `--pr`, `--issue`, `--linear-issue`, `--gitlab-issue`, and `--gitlab-mr`. References persist before setup or agent startup.
- **Find:** a full URL or native issue key; bare numbers are rejected. Keys search all matching sources. Reads stored metadata, without provider requests or conversation searches. Use `dolphin search` for conversation text.
- **Scope:** `--worktree` selects a worktree or folder workspace. Find also accepts `--repo` instead, plus `--include-archived` and `--limit` (default 50 workspaces). `truncated: true` means more matched. Remote selectors refer to the execution host; `current` is local only.
- **Output:** list returns `references` with opaque `key` and `selected`; writes also return `changes`. Worktree show/list/ps retain `linkedItems`. Find returns workspace matches and agents with `linked`, `liveness`, and available `terminal`/`mailbox` addresses. `linked: false` means ownership is unknown; sharing a workspace is insufficient evidence.

Choose an agent from `find`, then use its exact address:

```bash
dolphin terminal send --terminal '<terminal-from-find>' --text 'Status?' --enter
dolphin orchestration send --to '<mailbox-from-find>' --subject 'Status?' --type question
```

Mailboxes are `dispatch:<id>` or `orca_session_id:<id>`; a `run:<id>` addresses a coordinator. Find never sends messages or assigns ownership. Adding references from a shell does not associate that shell with an agent.

## Terminals

```bash
dolphin terminal list --worktree active --json
dolphin terminal show --terminal <handle> --json
dolphin terminal read --terminal <handle> --json
dolphin terminal read --terminal <handle> --screen --json
dolphin terminal read --terminal <handle> --cursor <cursor> --limit 1000 --json
dolphin terminal send --terminal <handle> --text "continue" --enter --json
dolphin terminal wait --terminal <handle> --for tui-idle --timeout-ms 300000 --json
dolphin terminal create --worktree active --title "tests" --command "npm test" --json
dolphin terminal split --terminal <handle> --direction horizontal --command "npm run dev" --json
dolphin terminal rename --terminal <handle> --title "runner" --json
dolphin terminal set-pane-title --terminal <handle> --title "reviewer" --json
dolphin terminal switch --terminal <handle> --json
dolphin terminal close --terminal <handle> --json
dolphin terminal close --worktree active --all --json
```

Omit `--terminal` to target the active terminal in the current worktree. Read before sending when you are not sure what the terminal is waiting for.

Close stops the process as part of removing the terminal. Use `--terminal <handle>` for one
terminal, or `--worktree <selector> --all` to durably close every terminal in exactly that
workspace, including its saved layouts and agent-resume records. Use workspace Sleep when those
terminals should resume later. If the execution host cannot confirm that every PTY stopped, bulk
close returns a failing `unverifiable` result rather than claiming the processes exited.
`terminal stop` remains only for compatibility with older tooling.

<Callout title="Terminal handles">
  Terminal handles are runtime-scoped. If Dolphin restarts or a command reports a stale terminal
  handle, run `dolphin terminal list --json` and reacquire the handle.
</Callout>

`terminal list` reports each terminal's `executionHostId` when Dolphin can verify it, plus a result-level `hostScope` with covered and omitted host IDs. Treat a missing host identity or scope as **unverifiable**, not local. A missing terminal is evidence that it exited only when its execution host is listed in `hostScope.hostIds`.

By default, `terminal read` returns the accumulated output stream with terminal escapes stripped. Programs that redraw lines can therefore appear as stacked fragments. Use `--screen` when you need the currently rendered frame; the response's `source` identifies `stream`, `screen`, or `screen-unavailable`. Screen reads have no history to page, so `--screen` and `--cursor` are mutually exclusive.

For long output, use cursor reads. Save `nextCursor` from one stream read, then pass it back with `--cursor` to fetch only new output.

## Chats

```bash
dolphin chat rename --session <sessionId> --name "Release notes" --json
dolphin chat rename --name "Migrate auth"
```

Renames a chat tab, the same as renaming it by hand. `--session` takes the `sessionId` that `dolphin agent launch` prints. Run inside a chat, it defaults to that chat; with `--environment` it is required.

Agents that run as chats are read and messaged with `chat` commands. `--session` takes the session id from `chat list` or the handle `agent launch` returns.

```bash
dolphin chat list --json
dolphin chat list --state working --json
dolphin chat read --session <session> --limit 10 --json
dolphin chat send --session <session> --text "Run the tests, then summarize failures" --json
dolphin chat send --session <session> --text "<message>" --wait --timeout-ms 600000 --json
dolphin chat wait --session <session> --timeout-ms 600000 --json
```

`chat read` returns the newest messages, tool calls, errors, approvals and questions; an approval or question waiting for an answer has `pending: true`. `chat send` sends the text as your message. While the agent is working, hosts with a message queue hold it until the turn ends and report `delivery: "queued"`. A chat that restarted since it was read refuses the send. `--text-file -` reads the message from stdin.

`chat send --wait` and `chat wait` return once the chat's own turn settles, in the words `chat list` uses: `settled: "done"`, or `settled: "blocked"` when an approval or question needs an answer. Background agents the chat started can still show as `working` or `waiting` in `chat list`. They print the entries since the last user message. A wait past `--timeout-ms` returns `settled: "timeout"`, and a message held in a stopped or failed queue returns `settled: "held"`; both exit 1. `chat read --json` returns a `cursor` for the newest row read, and `truncated: true` when older rows it needed were past the 200-row read. `chat list --state` takes `working`, `blocked`, `waiting` or `done`. Paired hosts (`--environment`, `--pairing-code`) can list chats but not read, send or wait yet.

## Files

```bash
dolphin file open src/App.tsx --worktree active --json
dolphin file open src/App.tsx --line 42 --column 7 --worktree active --focus --json
dolphin file diff src/App.tsx --staged --worktree active --json
dolphin file open-changed --mode both --worktree active --json
```

Paths are relative to the selected worktree. `--line` and `--column` are 1-based; a column requires a line. Positions are applied when you select the file, or immediately with `--focus`. Markdown switches to source view for positioning. Older hosts open the file without positioning. `open-changed` reads git status and opens changed files in edit, diff, or both modes. Tabs open without changing what you are looking at; pass `--focus` to be brought to them.

## Built-in browser

Browser commands control Dolphin's embedded browser tab for the selected worktree. They do not control Chrome, Safari, or the Dolphin desktop UI.

Use a snapshot -> act -> snapshot loop:

```bash
dolphin goto --url http://localhost:3000 --worktree active --json
dolphin snapshot --worktree active --json
dolphin click --element @e3 --worktree active --json
dolphin fill --element @e1 --value "user@example.com" --worktree active --json
dolphin wait --text "Welcome" --worktree active --json
dolphin screenshot --worktree active --json
```

Refs such as `@e3` come from `snapshot`. Re-snapshot after navigation, tab switches, clicks that change the page, and any stale-ref error.

`snapshot --interactive` lists only controls and links, `--delta` returns only what changed since the last `--delta` snapshot, and `--selector <css>` or `--depth <n>` narrow the tree. `screenshot` and `full-screenshot` save the image where the CLI runs and print its path; `screenshot` is in CSS pixels in Dolphin's desktop browser.

Tab and capture commands:

```bash
dolphin tab list --worktree active --json
dolphin tab create --url http://localhost:3000 --worktree active --json
dolphin tab switch --index 1 --worktree active --json
dolphin capture start --worktree active --json
dolphin console --limit 50 --worktree active --json
dolphin network --limit 50 --worktree active --json
dolphin full-screenshot --worktree active --json
dolphin pdf --worktree active --json
```

Use `dolphin exec --command "<agent-browser command>" --json` only for browser actions that do not have a typed Dolphin command yet.

Browser device emulation:

```bash
dolphin set device --name "iPhone 12" --worktree active --json
dolphin screenshot --worktree active --json
```

## Mobile emulator

The mobile emulator commands control iOS Simulator devices through Dolphin's worktree-scoped bridge. Use them instead of raw `serve-sim` or `simctl` when an agent is operating from inside Dolphin, so lifecycle and active-device state stay attached to the current worktree.

```bash
dolphin emulator list --worktree active --json
dolphin emulator attach "<device-name-or-udid>" --worktree active --json
dolphin emulator tap 0.5 0.7 --worktree active --json
dolphin emulator type "hello" --worktree active --json
dolphin emulator gesture '[{"type":"begin","x":0.5,"y":0.8},{"type":"move","x":0.5,"y":0.4},{"type":"end","x":0.5,"y":0.2}]' --worktree active --json
dolphin emulator button home --worktree active --json
dolphin emulator rotate landscape_left --worktree active --json
dolphin emulator exec --command "tap 0.5 0.7" --worktree active --json
dolphin emulator kill --worktree active --json
dolphin emulator shutdown --worktree active --json
```

Coordinates are normalized from `0` to `1`. Prefer `tap` for single taps, and use `gesture` for drags or multi-step touch input. Pass `--device <udid-or-name>` or `--emulator <id>` when a script must target a specific simulator instead of the worktree's active emulator.

## Linear

The `dolphin linear` surface is what agents use via the `dolphin-linear` skill (legacy install name `linear-tickets` still works). Prefer `--json`. Linked worktrees resolve with `--current`.

### Read

```bash
dolphin linear issue --current --full --json
dolphin linear issue ENG-123 --comments --children --relations --activity --json
dolphin linear search "auth bug" --workspace all --json
dolphin linear list --filter assigned --limit 10 --json
dolphin linear list-issues --team ENG --state started --assignee me --json
dolphin linear list-issues --query auth --updated-at -P7D --cursor <cursor> --workspace <id> --json
dolphin linear team list --json
dolphin linear team states --team ENG --json
dolphin linear team labels --team ENG --json
dolphin linear project list --query launch --json
```

`--full` expands comments, children, attachments, relations, and activity. Section flags (`--comments`, `--children`, `--attachments`, `--relations`, `--activity`) work individually.

### MCP-style write

```bash
# Create or update (omit id/--current to create; requires --team and --title on create)
dolphin linear save-issue --team ENG --title "Fix auth" --priority high --json
dolphin linear save-issue ENG-123 --state "In Progress" --assignee me --json
dolphin linear save-issue --current --project null --due-date null --json

dolphin linear relation add ENG-1 --related ENG-2 --type blocks --json
dolphin linear relation remove ENG-1 --related ENG-2 --type related --json
```

`save-issue` labels **replace** the full label set (Linear MCP `save_issue` semantics). Literal `null` clears assignee, estimate, due date, project, or parent.

### Field helpers (still valid)

```bash
dolphin linear status set --current --to "In Progress" --json
dolphin linear assignee set --current --me --json
dolphin linear priority set ENG-123 --to high --json
dolphin linear estimate set --current --to 3 --json
dolphin linear due-date set --current --to 2026-08-01 --json
dolphin linear label add --current --label backend --json
dolphin linear comment add --current --body "Investigating regression" --json
dolphin linear attach --current --url https://example.com/repro --title "Repro" --json
dolphin linear create --title "Flaky login test" --team ENG --priority high --json
```

Run `dolphin linear --help` or `dolphin skills get dolphin-linear` for the version-matched list. Pass an explicit issue id (e.g. `ENG-123`) when a script may run outside a Dolphin-linked worktree.

## Skills (local, no runtime required)

List bundled guides, print a version-matched guide, or install/update hybrid skill packages without the desktop Settings UI:

```bash
dolphin skills list
dolphin skills get dolphin-cli
dolphin skills get orchestration --references
dolphin skills get orchestration --reference recovery-and-cleanup
dolphin skills get orchestration --full
dolphin skills install --skill dolphin-cli --skill orchestration
dolphin skills install --all --dry-run
dolphin skills update --all
```

`install` / `update` run Dolphin's own skill installer on the machine that runs them, the same planner the app's **Update skills** uses. They do not contact the Dolphin runtime or need `npx`. See [Dolphin skills](/docs/cli/skills#keep-skills-up-to-date).

## Account (host-local runtime)

On a headless host running Dolphin (`dolphin serve` or the desktop app), add managed Claude/Codex accounts when the remote client cannot use **Add account** (remote runtime scope disables that button):

```bash
dolphin account list
dolphin account add                 # Claude by default
dolphin account add --agent codex
```

`account add` runs `claude login` / `codex login` in **this** terminal on the host, then registers the captured credentials with the local runtime. Codex uses device authorization so the browser can finish on another machine. Run these on the machine that owns the accounts — not through a client-only remote session.

Switch which saved account new agents launch with, for any provider with saved accounts (Claude, Codex, OpenCode, Devin, Antigravity):

```bash
dolphin account list                                               # ids, emails/labels, and the active one
dolphin account select --agent claude --account you@example.com    # id, email or label
dolphin worktree create --name task --agent claude --prompt "..."
dolphin account select --agent claude --account system             # back to your own sign-in
dolphin account rm --agent codex --account old@example.com         # forget a saved account
```

A selection applies to every agent of that provider launched on the host after it — the same switch as the status-bar account menu — not to a single workspace. An email shared by several accounts (one sign-in in two organizations) is refused; pass the id instead. Antigravity has no `system` default, and `account rm` never removes system credentials.

## Artifacts

Publish HTML or Markdown through the signed-in Dolphin account. Viewing a public link does not require sign-in; create/list/update/delete do. Publishing follows **Settings → Artifacts → Allow publishing public artifact links** on the device: on by default for new profiles, while profiles created before this default keep their previous setting. Only a human can change it; there is no CLI flag that grants the gate. `list`, `unshare`, and `delete` stay available so you can audit or revoke links after turning publishing off.

```bash
dolphin artifacts share ./report.html --json
dolphin artifacts share ./notes.md --json
dolphin artifacts update ./notes.md --json
dolphin artifacts unshare ./notes.md --json
dolphin artifacts list --json
dolphin artifacts list --cursor <cursor> --json
dolphin artifacts delete <id> --json
```

- Accepted files: `.html`, `.htm`, `.md`, `.markdown`.
- `share` stores the edit token in the active Dolphin profile and does not print it. `update` / `unshare` resolve by the same local path and profile that originally shared the file.
- `list` is paged (`nextCursor` → `--cursor`). `delete` takes the artifact id from `list` and does not need the original file.
- Relative HTML assets are not uploaded — share self-contained HTML or absolute asset URLs.
- Denied publish/update fails with `artifact_sharing_disabled`; fix Settings instead of retrying.
- Headless Dolphin servers have no Dolphin cloud sign-in, so artifact and skill-sharing commands there fail with `sharing_unavailable_on_host`; share from the desktop app.
- Desktop: open a local HTML or Markdown file and use **Share as artifact**, or manage links from the sidebar **Artifacts** page.


## Agent habits

- Prefer `--json` for automation and agent calls.
- Prefer selectors over parsing UI labels.
- Read terminal state before sending input unless the next input is obvious.
- Use worktree comments for progress checkpoints. See [Worktree checkpoints](/docs/cli/worktree-checkpoints).
- Use [Orchestration](/docs/cli/orchestration) for tracked multi-agent dispatches instead of ad hoc terminal prompts.
